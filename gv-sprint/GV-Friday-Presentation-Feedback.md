# Prototype Presentation and Feedback

The overall feedback on our PowerPoint prototype was positive. It confirmed that the current direction of the project is promising and that the prototype addresses a relevant problem space.

## Key Feedback Points

One important point of feedback was that the optimization problem domain should be reduced in complexity. Instead of trying to support a broad range of optimization problems, the project should initially focus on a clearly defined subset.

For the current scope, it is sufficient to focus on models that address:

- the optimal order quantity,
- the optimal order timing.

In addition, the objective function can initially be limited to cost minimization. This keeps the optimization logic more focused and makes the system easier to design, implement, and evaluate.

## Input Options

The prototype currently includes two main input methods:

structured form input,
iterative chat-based input.

The feedback also highlighted that additional input methods could be added later. In particular, document-based input could be useful for extracting relevant information from existing business documents.

Possible examples include:

- supplier contracts,
- PDF documents,
- terms and conditions,
- master data exported from ERP systems,
- other documents containing relevant procurement or inventory information.

These documents could later be uploaded, processed, and used as additional input sources for the optimization model. This would make the system more flexible and allow it to incorporate information that is already available in existing company documents.

## Conclusion

The feedback supports the current prototype direction while also suggesting a more focused initial scope. By concentrating on optimal order quantity, optimal order timing, and cost minimization, the project can provide a clear and realistic foundation. Additional input methods, such as document uploads, can be considered as future extensions once the core functionality is established.
